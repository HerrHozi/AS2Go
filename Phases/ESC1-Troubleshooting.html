Troubleshooting PKINIT: KDC_ERR_PADATA_TYPE_NOSUPP

When requesting a Kerberos TGT using certificate-based authentication with Rubeus, you may encounter:

Output
[*] Action: Ask TGT
[*] Using PKINIT with etype aes256_cts_hmac_sha1
[X] KRB-ERROR (16) : KDC_ERR_PADATA_TYPE_NOSUPP

Before troubleshooting the client certificate or account mapping, check the KDC certificate on the domain controller handling the request.

In my lab, the cause was an expired certificate issued from the Kerberos Authentication template. The KDC could no longer find a suitable certificate for PKINIT.

Technically, it is the certificate—not the template—that expires. The template defines how the CA issues certificates.

1. Check the domain controller’s event log

Run the following on the DC targeted by the PKINIT request:

PowerShell
Get-WinEvent -FilterHashtable @{
    LogName      = 'System'
    ProviderName = 'Microsoft-Windows-Kerberos-Key-Distribution-Center'
    StartTime    = (Get-Date).AddHours(-1)
} -ErrorAction SilentlyContinue |
    Select-Object TimeCreated, Id, Message |
    Format-List

In this case, the following events confirmed the problem:

Event IDMessage
19The KDC is unable to use PKINIT because it is missing a suitable certificate.
29The KDC cannot find a suitable certificate for smart card logons, or the certificate could not be verified.
32The KDC uses a certificate without the KDC Authentication EKU.

These events provide stronger evidence than the Rubeus error alone. Microsoft also recommends checking KDC-related event logs when troubleshooting Kerberos authentication.

2. Check the DC’s certificates

List certificates containing the KDC Authentication EKU:

PowerShell
Get-ChildItem Cert:\LocalMachine\My |
    Where-Object {
        $_.EnhancedKeyUsageList.ObjectId -contains '1.3.6.1.5.2.3.5'
    } |
    Select-Object Subject, NotBefore, NotAfter,
                  HasPrivateKey, Thumbprint,
                  EnhancedKeyUsageList |
    Format-List

Check that the certificate:

  • Is currently valid.
  • Has an associated private key.
  • Contains KDC Authentication — OID 1.3.6.1.5.2.3.5.

Microsoft recommends the Kerberos Authentication template for DC certificates and highlights the KDC Authentication EKU as a requirement for the relevant certificate-based authentication scenarios.

For additional details, including the certificate template and Subject Alternative Name, use:

PowerShell
certutil.exe -v -store My

If a suitable certificate exists but authentication still fails, investigate certificate-chain trust and revocation checking rather than assuming that enrollment alone resolves the issue.

3. Request a new Kerberos Authentication certificate

On the affected DC, open:

PowerShell
certlm.msc

Navigate to:

Navigation
Personal → Certificates
  → Right-click
  → All Tasks
  → Request New Certificate
  → Active Directory Enrollment Policy
  → Kerberos Authentication
  → Enroll

If the template is unavailable:

  1. On the Enterprise CA, open certsrv.msc.
  2. Right-click Certificate Templates.
  3. Select New → Certificate Template to Issue.
  4. Publish Kerberos Authentication.
  5. In certtmpl.msc, verify that the intended DCs have Read and Enroll permissions. Add Autoenroll if automatic enrollment is required. Template publication and enrollment permissions must both be configured.

Do not delete existing DC certificates indiscriminately; they may still serve other purposes.

4. Validate and prevent recurrence

After enrollment, verify the new certificate and repeat the PKINIT request against the same DC. Check for newly generated events 19 or 29; historical events will remain in the log.

To prevent another expiry-related outage, configure a GPO applying to the domain controllers:

Group Policy
Computer Configuration
  → Policies
  → Windows Settings
  → Security Settings
  → Public Key Policies
  → Certificate Services Client – Auto-Enrollment

Enable automatic enrollment and select:

  • Renew expired certificates, update pending certificates, and remove revoked certificates
  • Update certificates that use certificate templates

Autoenrollment also requires the appropriate template permissions and CA publication.

Takeaway

KDC_ERR_PADATA_TYPE_NOSUPP during PKINIT is a reason to check the DC’s certificate first—not proof that the client certificate is invalid. In this case, KDC events 19 and 29, together with an expired Kerberos Authentication certificate, identified the server-side problem. Successful enrollment still needs to be followed by an actual authentication test.
